Observability Fundamentals
Introduction

Modern applications run across multiple servers, containers, cloud services, databases, APIs, and networks. When something goes wrong, engineers need visibility into the system to quickly identify and resolve issues.

Observability helps teams understand the internal state of a system by examining its outputs such as metrics, logs, traces, and alerts.

Monitoring vs Observability
Monitoring

Monitoring is the process of collecting and tracking predefined system information.

Examples:

CPU utilization
Memory usage
Disk space
Network traffic
Application availability

Monitoring tells us when something exceeds an expected threshold.

Example
CPU Usage = 95%

Monitoring detects the problem.

Observability

Observability is the ability to understand why a problem is happening by analyzing system data.

Observability goes beyond monitoring.

It helps answer:

Why is the application slow?
Which service failed?
What request caused the issue?
Which database query is creating delays?
Example

Monitoring shows:

CPU = 95%

Observability helps determine:

Which service caused the CPU spike?
Which user request triggered it?
What happened before the spike?
Monitoring vs Observability Summary
Monitoring	Observability
Detects issues	Explains issues
Uses predefined metrics	Investigates unknown problems
Reactive	Investigative
Shows symptoms	Finds root causes
Logging
What is Logging?

Logs are timestamped records generated by applications, operating systems, or cloud services.

Logs capture events occurring within a system.

Examples

Application startup:

2026-09-28 10:00:00 Application Started

User login:

2026-09-28 10:05:00 User Login Successful

Database error:

2026-09-28 10:10:00 Database Connection Failed
Why Logs Matter

Logs help answer:

What happened?

Engineers use logs to:

Troubleshoot failures
Investigate incidents
Audit user activity
Identify application errors

Metrics
What are Metrics?

Metrics are numerical measurements collected over time.

Metrics help track system performance and health.

Examples:

CPU utilization
Memory usage
Request count
Response time
Error rate
Why Metrics Matter

Metrics answer:

What is happening?

Examples:

CPU = 80%
Memory = 65%
Response Time = 200ms

Metrics provide a high-level view of system health.

Metric Flow
Application
     │
     ▼
Metric Collection
     │
     ▼
CloudWatch Metrics
     │
     ▼
Dashboard
Tracing
What is Tracing?

Tracing follows a request as it travels through different services.

Tracing is extremely useful in microservices architectures.

Example Request Journey
User Request
      │
      ▼
Load Balancer
      │
      ▼
Application Service
      │
      ▼
Database
      │
      ▼
Response

Tracing records each step and its execution time.

Why Tracing Matters

Tracing helps answer:

Where is the delay occurring?

Example:

Load Balancer = 10ms
Application = 40ms
Database = 800ms

Result:

Database is causing the slowdown.
Alerting
What is Alerting?

Alerting automatically notifies engineers when predefined conditions are met.

Alerts help teams respond quickly before users are impacted.

Examples

CPU Alert:

CPU > 80%

Memory Alert:

Memory > 90%

Error Alert:

HTTP 5xx Errors > 50

        ▼

Dashboards
What is a Dashboard?

A dashboard is a visual representation of system health and performance.

Dashboards combine multiple metrics into a single view.

Examples:

CPU usage
Memory utilization
Request count
Error rate
Application latency
Dashboard Example
+----------------------------------+
| CPU Usage        42%             |
| Memory Usage     68%             |
| Error Rate       0.2%            |
| Response Time    150ms           |
+----------------------------------+
Dashboard Purpose

Dashboards answer:

What is the current health?

Real-World Example

A website becomes slow.

Metrics show
CPU = 90%
Logs show
Database timeout errors
Traces show
Database query taking 2 seconds
Alarm triggers
Response Time > 1 second
Dashboard shows
High CPU
High Latency
Increased Error Rate
Conclusion

The database query is causing performance issues.

Observability helped identify the root cause quickly.

Key Takeaways
Monitoring detects problems.
Observability explains problems.
Metrics show what is happening.
Logs show what happened.
Traces show where delays occur.
Alerts notify teams when action is needed.
Dashboards provide real-time visibility.
Metrics, Logs, and Traces form the foundation of observability.
AWS CloudWatch and AWS X-Ray are common observability tools used in cloud environments.
Effective observability reduces downtime and speeds up troubleshooting.
