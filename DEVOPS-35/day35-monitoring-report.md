2. ECS CPU Usage
What is ECS CPU Usage?

ECS CPU utilization shows how much CPU capacity is being used by the ECS service or tasks.

It helps identify whether the application is:

Under low load
Operating normally
Experiencing high CPU usage
Potentially requiring additional capacity
CloudWatch Metric

For an ECS service, commonly used metrics include:

AWS/ECS

Important dimensions can include:

ClusterName
ServiceName

Metric:

CPUUtilization
Example
ECS CPU Utilization = 45%

This means the monitored ECS service is using approximately 45% of its available CPU capacity during the selected period.

Investigation

Open:

AWS Console
   ↓
CloudWatch
   ↓

   ↓

   ↓

4. ALB Response Time
What is Response Time?

ALB response time measures the time taken for the load balancer to receive a response from the target.

This is useful for identifying application latency.

CloudWatch Metric

Namespace:

AWS/ApplicationELB

Metric:

5. ALB 5XX Errors
What are 5XX Errors?

HTTP 5XX errors indicate server-side failures.

Examples:

500 Internal Server Error
502 Bad Gateway
503 Service Unavailable
504 Gateway Timeout

ALB monitoring can help identify failures occurring at the load balancer or target/application layer.

Important Metrics

Useful ALB metrics include:

HTTPCode_ELB_5XX_Count
HTTPCode_Target_5XX_Count
HTTPCode_ELB_5XX_Count

Counts HTTP 5XX responses generated by the load balancer.

HTTPCode_Target_5XX_Count

Counts HTTP 5XX responses generated by targets.

6. RDS CPU Utilization
What is RDS CPU Utilization?

RDS CPU utilization shows how much CPU capacity is being used by the database instance.

High CPU usage may indicate:

Heavy database workload
Expensive queries
Increased application traffic
Insufficient database capacity

CPU alone does not prove the cause, so it should be investigated together with other RDS metrics and database logs.

CloudWatch Metric

Namespace:

AWS/RDS

Metric:

CPUUtilization

Dimension:

DBInstanceIdentifier
Investigation

Navigate to:

CloudWatch
   ↓
Metrics
   ↓
RDS
   ↓
Per-Database Metrics
   ↓
CPUUtilization

Select the RDS instance used by the application.

7. ECS Application Errors
What are ECS Application Errors?

Application errors are error messages generated by the application running inside the ECS container.

Examples:

ERROR Database connection failed
ERROR Request processing failed
ERROR Internal server error
Exception
Timeout
Connection refused

These logs are usually available through the ECS task's configured CloudWatch log group.

For this training environment:

/ecs/devops-training-app
8. Search ECS Application Errors

Open:

AWS Console
   ↓
CloudWatch
   ↓
Logs
   ↓
Logs Insights

Select:

/ecs/devops-training-app

Use:

fields @timestamp, @message
| filter @message like /ERROR/
| sort @timestamp desc
| limit 20
Search Exceptions
fields @timestamp, @message
| filter @message like /Exception/
| sort @timestamp desc
| limit 20
Search Timeouts
fields @timestamp, @message
| filter @message like /Timeout/
| sort @timestamp desc
| limit 20
Search Connection Problems
fields @timestamp, @message
| filter @message like /Connection/
| sort @timestamp desc
| limit 20

Record:

________________________

If no matching errors are found, record:

Do not create or assume error counts that were not actually observed.

12. What Each Metric Tells Us
Metric	Main Question
ECS CPU	Is the ECS workload using significant CPU?
ALB Request Count	How much traffic is reaching the load balancer?
ALB Response Time	How long are targets taking to respond?
ALB 5XX	Are server-side failures occurring at the ALB?
Target 5XX	Are targets returning server-side errors?
RDS CPU	How much CPU is the database using?
ECS Logs	What errors are occurring inside the application?
13. Troubleshooting Relationship

Monitoring becomes more useful when metrics are analyzed together.

For example:

ALB Request Count
       │
       ▼
Traffic increases
       │
       ▼
ECS CPU increases
       │
       ▼
Application response time increases
       │
       ▼
ALB TargetResponseTime increases
       │
       ▼
Application may generate errors
       │
       ▼
ECS Logs

At the same time:

RDS CPU
   │
   ▼
Check database workload

This allows the engineer to correlate different signals instead of investigating a single metric in isolation.

17. Key Takeaways
CloudWatch Metrics provides numerical information about AWS resources.
ECS CPU utilization helps monitor container workload.
ALB RequestCount shows traffic handled by the load balancer.
ALB TargetResponseTime helps monitor target response latency.
ALB 5XX metrics help identify server-side failures.
RDS CPU utilization helps monitor database resource usage.
ECS application logs provide detailed information about application failures.
Metrics and logs should be correlated using timestamps.
Do not assume that a high metric automatically identifies the root cause.
Actual monitoring values should always be taken from the AWS environment.
