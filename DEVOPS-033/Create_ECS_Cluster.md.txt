What is AWS Fargate?

AWS Fargate is a serverless compute engine for containers.

It runs your containers without requiring you to create or manage EC2 servers.

Instead of:

Create EC2
Install Docker
Patch OS
Manage Capacity
Monitor Server

You simply tell AWS:

Run this container
CPU = 0.5 vCPU
Memory = 1 GB

AWS handles the infrastructure.

Traditional ECS (EC2 Launch Type)

In the EC2 launch model, ECS manages containers but you manage the servers.

CPU in Fargate

Every Fargate task needs CPU.

CPU defines processing power available to the container.

Example:

CPU = 256

Meaning:

0.25 vCPU

Common Values:

Task Networking

What is an ENI?

ENI = Elastic Network Interface

Think of it as:

Virtual Network Card

When ECS launches a Fargate task:

Fargate Task
       │

       │
       ▼
Gets Private IP

Example:

Task A

Task B
IP: 10.0.1.31

Each task receives its own network identity.

IAM Roles

Containers often need AWS permissions.

Examples:

Read Secrets Manager
Write CloudWatch Logs
Read S3

Never place AWS keys inside containers.

Bad:

AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY

Good:

      │
      ▼

      │
      ▼

This is more secure and follows AWS best practices.

Key Takeaways
Fargate is a serverless container runtime for ECS.
You do not manage EC2 instances, Docker installation, or OS patching.
Every Fargate task requires CPU and Memory allocation.
Each task receives its own Elastic Network Interface (ENI) and private IP.
Tasks run inside subnets within a VPC.
Security Groups control network access to the tasks.
IAM Roles provide secure access to AWS services.
Fargate manages infrastructure, but you must still design and configure networking, security, and permissions correctly.
